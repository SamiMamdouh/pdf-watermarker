ISM — PDF WATERMARK STUDIO

PUBLIC GITHUB PAGES VERSION

The browser app is published at https://samimamdouh.github.io/pdf-watermarker/.
This is a public static site with no login or access control. PDFs and names
stay in the visitor's browser; never put credentials or private documents here.

The separately hosted Node.js version below uses a shared username and
password. GitHub Pages cannot run that server or enforce its login.

NODE.JS EDITION: USERNAME AND PASSWORD

This Node.js edition runs independently from ChatGPT Sites. Visitors use the app's
username and password. ChatGPT sign-in is not part of this edition.
It currently uses ONE SHARED ACCOUNT, with no public registration or
individual accounts. Share the credentials with the people you authorize.

QUICK LOCAL START

Install Node.js 22 or newer. No npm dependencies need to be installed.
In this extracted folder run:

  npm run setup
  npm start

Setup generates a random password for username admin and displays it once.
Save it in your password manager. Only its salted scrypt hash is written
to the local .env file. Setup refuses to overwrite an existing .env file.
To choose a different username: npm run setup -- your-username

Open http://127.0.0.1:3000 and sign in. On Mac, Start.command runs setup
when needed and starts the app; keep its terminal window open.

DEPLOY THE AUTHENTICATED NODE.JS EDITION TO YOUR OWN HOST

Choose a host that can run a Node.js server or the included Dockerfile.
A static-only host cannot enforce this login. Serve the app over HTTPS.

Upload this folder without .env or .git. Set these SECRET environment
variables in your hosting dashboard:

  APP_USERNAME       Your chosen shared username
  APP_PASSWORD       A unique password of at least 12 characters
  NODE_ENV           production
  APP_ORIGIN         Your exact public origin, e.g. https://ism.example.com

APP_ORIGIN has no trailing slash or path. Your host normally supplies PORT;
the default is 3000. Start command: npm start. No build command is required.
The Node server binds to 0.0.0.0 in production. Health check path: /healthz.
The host/reverse proxy must provide HTTPS. Do not serve public/ separately:
all visitors must go through server.mjs to enforce authentication.

RENDER

This repository includes render.yaml for a Render Blueprint web service.
Create a Blueprint from the repository and provide APP_USERNAME and
APP_PASSWORD when prompted. After Render assigns the service URL, set
APP_ORIGIN to that exact HTTPS origin in the service's environment, then
deploy. Keep a single service instance; sessions are stored in memory.

For a stored hash instead of APP_PASSWORD, copy APP_USERNAME and
APP_PASSWORD_HASH from the .env generated by setup into your host's secret
settings, then omit APP_PASSWORD. The hash takes precedence when both exist.
Do not include surrounding quote marks when entering the hash in a hosting
dashboard. Never place passwords or hashes in browser JavaScript or HTML.

Optional TRUST_PROXY=true: enable only if your trusted reverse proxy
appends or replaces X-Forwarded-For and the Node server is unreachable
directly. This lets the login limiter distinguish visitors behind the
proxy. The default is false; then users may share a per-proxy attempt limit.

SINGLE INSTANCE

Run one Node process/instance. Sessions and attempt counters are in memory.
Each session lasts eight hours. Restarting signs everyone out. A shared
session store is needed before running multiple instances or replicas.
The server limits failed logins, but this is a small shared-access app,
not an enterprise identity system. There is no password-recovery email.

CHANGE CREDENTIALS

On a host, change APP_USERNAME and APP_PASSWORD (or APP_PASSWORD_HASH) in
secret settings, then restart. Remove an old APP_PASSWORD_HASH if switching
to APP_PASSWORD. Restarting revokes all existing sessions.
Locally, rename the old .env file, then rerun setup and restart.

USING THE APP

Sign in, select a PDF, and enter names one per line. Arabic and English
are supported. Adjust the watermark, then select Preview all copies.
Each name receives the complete source document in name-list order.
Review the combined PDF before selecting Print copies or Download PDF.
The Sign out button ends that browser's session.

PDFs and names remain in the visitor's browser; they are never sent to
this server. Credentials are submitted to the server to sign in. PDF
generation and preview are unchanged from the original app.

Limits: 40 MB PDF, 150 names, 1,500 output pages. Password-protected PDFs
are unsupported. Large print runs may need smaller batches. If embedded
preview or printing fails, open or download the PDF and use a PDF viewer.

FILES AND VALIDATION

server.mjs        HTTP server, protected files, sessions, login and logout
auth.mjs          Scrypt password hashing and verification
setup.mjs         Generates credentials and a local configuration
login.html/css    Login screen
public/           PDF application, bundled libraries, font, and licenses
test/             Authentication integration tests; run npm test
Dockerfile        Optional production container, runs as a non-root user
render.yaml       Render Blueprint service configuration

Automated checks cover sign-in, protected files, incorrect credentials,
session expiry, logout, form-origin checks, attempt limits, and configuration.
Browser layout and the physical print dialog still require a manual check.

Dependencies: pdf-lib 1.17.1, PDF.js 4.10.38, Noto Sans Arabic.
Their licenses are in public/vendor. The Node server uses built-in modules.
